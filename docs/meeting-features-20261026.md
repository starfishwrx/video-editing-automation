# 10月26日会议功能实现候选

基于 `main@e4b270b`，分支 `codex/meeting-features-20261026`。对应[会议计划 F01–F08](plans/20261026_feature_plan.md)。本分支不合入纸品规则草稿 PR #15，不部署、不合并、不修改飞书表结构。运行包版本仍由 `VERSION` 读取（1.5.6）。

## 使用与行为

| 功能 | 源码行为 |
| --- | --- |
| F01 音色及倍速 | 先拆名称后缀，再唯一匹配官方音色，合成或复用原始音频，再应用一次倍速。显式 `voice_tempo`（包括 1.0）优先于名称后缀，再取品类默认。TTS 范围 0.5–2.0，非法值报错。显式任务音色优先于继承的环境音色，预合成与最终合成共用同一身份。 |
| F02 音频字幕 | `ai_editor` 使用最终调速、静音和响度处理后的纯旁白时间轴，排除 BGM/素材原声；faster-whisper 返回词级时间，按停顿、标点和整词组织字幕。同句跨换镜只显示一次。原文只用于核对，不分摊出伪造时间。识别失败、品牌/数字或明显内容不一致保持未认证。 |
| F03 字幕轨 | 维护中的 JyProject wrapper 写统一的原生 `subtitle` 素材轨，样式 size 8、bold、X=0/Y=-0.55；不叠加中间整段文案。写后检查类型、文本、区间和唯一字幕轨。实际全选移动与保存重开仍需剪映验证。 |
| F04 BGM | 在适配脚本的候选池随机选择；同批优先不重复、耗尽轮换，同任务及脚本重试复用收据。明确 path/music_id 按指定值。处理源前导静音并核验可听内容，铺底从时间轴 0 开始。 |
| F05 速度与取段 | 正确卖点优先；相近质量优先可行的 ≤2 倍，原速合适仍用原速，必要时最高 20 倍。编排器看到实际求解速度和源窗。偏好原素材中后段，前三秒是软偏好，不对每个镜头加三秒硬裁切。 |
| F06 展示与重复 | 奶被纸、棉柔巾、厨房纸、湿厕纸保持卖点先行、同商品展示承接钩子；依据内容观察、源哈希及区间降低近重复。只剩唯一卖点候选时，必须明确记录稀缺复用理由；介绍/钩子不能使用此例外，连续实验仍须顺接。 |
| F07 单条任务 | 标准 worker 和 JyPoll 一份脚本生成一条视频。显式 `meeting_profile="legacy"` 保留旧批队列 count 兼容接口。 |
| F08 人工参考 | 可选倍速和修改后成品链接/附件经 JyPoll/task/manifest/done 保持同任务关联；原始音色及输入保留。参考存在或缺失均不推断通过，评价默认 `unknown`。现有 `reference_video` 仍是独立字段。 |

画面速度与 TTS 倍速分别处理，不相乘。全局 1 帧气口、零尾留白、无转场等已有规则保持回归；纸品 13 类动作合同及纸品字幕像素位置仍跟踪 PR #15。

## 本地配置

```powershell
cd packages/video-v1.5.3
uv sync --frozen --group asr
uv run --frozen --group asr python -X utf8 doubao-jianying-orchestrator/run.py build --input <manifest.json> --report-dir <new-report-dir>
```

首次 ASR 使用会下载模型（默认 `small`），可在 manifest 的 `asr_model` 或 `JY_ASR_MODEL` 指定已准备好的模型目录；`asr_language` 可填 `zh`。ASR 优先使用可用的 CUDA，缺少对应库时一次回退 CPU int8并记录；它与现有视频 GPU、队列及 GLM 20 路配置独立。可在启动环境设置 `HF_HUB_DOWNLOAD_TIMEOUT`，不自动读取 `.env`。识别超时或依赖缺失不回退旧字数字幕。

ASR 依赖组随默认 `uv sync` 安装，避免新版 AI 入口在普通安装后缺失识别依赖；仅使用 legacy 的安装可显式 `uv sync --no-group asr`。

`asr_timeout_s` 默认 180 秒，包含模型准备和识别；超时终止子进程并保留待审。商品名及显式 `brand_names` 可以提供热词提示，仍须以识别结果为准。常见中文/阿拉伯数字按数值核对；内容一致度不足0.95或保护词不符不能出认证字幕。

`caption_source="audio"` 可供显式 legacy 任务单独验证新字幕；`ai_editor` 必须使用音频字幕。完整回滚使用 `selection_mode="legacy"` 及旧字幕模式，不借回滚为新版结果认证。

```json
{
  "voice": "真人播客女1.3倍速",
  "voice_tempo": 1.0,
  "batch_id": "example-batch",
  "modified_reference_links": ["https://example.invalid/human-final"],
  "modified_reference_attachments": [],
  "meeting_profile": "meeting"
}
```

上例锁定“真人播客女”并只应用 1.0 倍。修改参考通过任务入口保存到 `meeting_inputs`，不由引擎抓取或自行评审参考链接。批处理为 BGM 传入共享状态目录和批次身份；独立 manifest 可配置 `bgm_state_dir`/`batch_id`，否则选曲收据限于自身 report 目录。

## 验证与待验项

离线测试、真实 ASR、草稿结构和剪映编辑验收分开记录。测试 ASR 注入只用于合同回归，不算真实识别成功。`caption_identity.json` 绑定最终纯旁白哈希、模型/设备/设置和原文身份，UI 验收初始为 `UNKNOWN`；规则或输入变化不能直接复用旧认证。

本轮的最终测试计数、真实观察及未完成项在 PR 验证部分记录。剪映窗口采集出现 `FrameArrived timed out`，因此未据原生字幕 JSON 声称全选移动已通过。真实模型观察、修改稿人工标签、成片验收尚不齐时保持草稿 PR。无头结构/媒体/时间回读可自动完成，实际界面行为仍单独待验。

最终离线回归：包级105项、编排器669项均通过；包含PowerShell字段映射/语法、真实FFmpeg前导静音、未知/超时拦截及新旧字幕兼容。测试中的ASR为显式注入，缓存夹具不依赖本机模型下载。

真实任务补充发现配音列还使用“真人播客女1.2”这类不带“倍速”的小数尾缀。身份解析、品类默认和TTS现在共用同一个拆解入口，兼容该写法；裸整数仍保留在音色名称中，显式倍速字段继续优先。新增回归覆盖唯一speaker、显式1.0覆盖、整数名称和非法小数倍率。实时表格行号会变化，验证先冻结当前视图及record身份，不按旧队列下标推断任务。

两组既有纸品任务的原始旁白复制到私有验证目录后，应用1.3倍并按多镜切片重建纯旁白：奶被纸短句实际识别通过；厨房纸出现“绒立方/厨房纸/抹布”错字，最终保持待审。由该反例收紧内容检查，并更新 ASR 合同身份，旧的宽松结果不能从缓存获得新版认证。本机 ASR 因缺少 `cublas64_12.dll` 回退 CPU；视频 GPU 配置未修改。两组音频观察不等于两条完整成片验收。

另通过正式 `run.py build --delivery-mode preview` 在独立草稿库生成技术预览：使用合成测试画面和已调速的奶被纸旁白，新 ASR 字幕写入成功，媒体存在且草稿回读通过。结果仍为 `UNCERTIFIED`，合成画面不能证明商品卖点，也没有参与业务分发。这验证写入链路，不作为真实选镜或成片验收。
