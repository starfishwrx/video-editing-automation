# 程序化视频生产与末端剪映草稿导出方案

状态：分期实施中。日期：2026-11-01。源码基线：feat/paper-shot-retiming @ b29e44573eb84cc1c856a9a3fc71f0b6ca92e4c0。

2026-11-02 接续：PR1 的固定输入时间线/资产边界与 PR2 的渲染/检查骨架已实现，使用显式命令，默认生产不切换。人工正确选镜集成、独立内容/观看验收和 PR3–PR5 尚未完成，详见[实际实现与边界](../programmatic-production.md)。下文基线描述仍保留为方案制定时的事实。

最终交付仍为可编辑剪映草稿，供专业编辑评审和精修。把剪映工程从生产过程中的主要数据载体，改为生产验收通过后的输出格式：选镜、切片、字幕、混音、预览和返工先围绕独立时间线完成，再从同一份已验收结果导出分轨草稿。

本文最初只形成实施方案；后续代码进度以顶部接续记录为准。尚未实现的接口、状态和模块名仍为拟议设计；默认架构与运行方式仍以 [架构说明](../architecture.md)、[Windows 流水线](../windows-pipeline.md) 为准。不部署、不注册计划任务、不运行真实队列。

## 1. 判断与范围

这个方向适合在当前分支继续推进。模块化、Windows 脚本运行、GLM/Qwen 直连、动作观察与帧域求解已经提供基础；下一步重点是拆分生产与输出职责，把隔离验证能力接成可独立运行的生产闭环。

“导出后移”主要改善可观察性、返工效率和输出边界。画面与口播是否匹配，还取决于素材事实、需求理解、候选召回、动作定位和实际播放效果，不能承诺换成程序渲染就自动消除误选。

本轮实施范围：

- 独立时间线，以及与口播、字幕、源素材和证据的关联。
- 最终音频、字幕和可编辑效果参数的提前确定。
- 无需剪映草稿的工作预览、内容质检和有界局部修复。
- 纸品动作观察与时序求解的受控接入。
- 已验收时间线到剪映草稿的保真映射、交付检查和编辑反馈。

继续复用现有 Python 功能包、FFmpeg、JyProject、dispatcher 和 tools/acceptance。暂缓微服务、新索引系统、全面更换模型或编码框架。Mac 交接、旧人工 prepare/collect、Gold 放行和 Codex/Anthropic/CCSwitch 运行链保持退役。

工作预览是验收用媒体产物，不改变最终交付为可编辑草稿的目标。formal 任务也需要工作预览；“渲染预览”不等于把 delivery_mode 改为 preview。尚未通过的工作结果不得进入正式成功状态或表格完成回写。

专业编辑是下游评审和精修角色，不恢复旧 Mac 审核运行链。编辑结果可采集为私有回归数据，不用人工标签代替程序要求的正式证据。

## 4. 独立时间线与数据合同

### 4.1 统一编辑结果

在现有 Clip/manifest 上演进完整的 EditTimeline，保存为任务目录内的 timeline.json。它由 application 编排产生；media 渲染器和 delivery 导出器共同消费。运行中的修改产生明确修订，质检只认对应修订与实际资产，不能靠复制 status 字段沿用旧通过。

时间线至少包含：

- 任务与修订身份、画布尺寸、目标 FPS、有理数帧率表达、总时长。
- 资产引用及原素材/可编辑派生素材关系；沿用已有素材身份核对。
- 视频源入出点、目标位置和长度、速度或连续分段变速、裁切/位置/透明度和已支持效果。
- 独立旁白、BGM、必要原声的源区间、目标时间、增益与淡变。
- 独立字幕的文本、起止、样式、布局，以及对应口播文本。
- 句 ID、镜头事件 ID、字幕 ID、卖点/动作需求与源证据关联。
- 已观察的动作/结果区间、边界不确定项和无法解决的需求。
- 目标剪映能力约束及实际使用的可映射功能。

整数微秒仍为跨模块业务时间。源帧号、源 PTS 和目标输出帧作为精确播放证据补充，不替换微秒合同。量化差、帧率换算及末帧选择由同一转换规则计算，两个输出端不得分别推算一套结果。

### 4.2 三种单位独立关联

口播句、字幕行和镜头分别编号；同一句可以多镜，同一连续动作可以承接多句。字幕换行只影响字幕事件，镜头更换保持已定配音，修改配音才触发相应时序重解。

一句多个卖点还需给出在真实音频中的时间区间。仅验证“整句卖点都出现了”不能保证播放顺序与口播一致。无法可靠细分时，优先使用覆盖整句的合适画面或明确待处理，不伪造精确词级时间戳，不为获得对齐而擅自改写原文。

### 4.3 先完成音频，再求最终时间线

音色、倍速、剪边、响度和最终文件时长在生产阶段确定。字幕基于这些实际音频构建。现有 TTS 缓存继续复用，禁止为了预览重复合成。

写稿器只消费已处理音频和字幕事件。若后处理改变时长，按实际结果重新求解受影响区间，而不是让两个输出端分别补齐。原音、旁白与 BGM 都保留独立资产和轨道。

## 5. 素材理解与选镜

### 5.1 分开可见事实和用途判断

第一层记录可复用的源素材事实：商品身份、对象/部位、动作阶段、可见结果、可读标称、真实帧号/PTS、观察范围及不确定边界。复用新分支已不含目标句长的 paper_action_events；观察阶段不输入所需速度或旧通过结论。

第二层记录文案需求及适配判断：哪些对象/动作必须直接对应，哪些句子允许普通产品展示或说明画面。包装文字可以支持标称，不能替代功能演示。感受性表达不统一强制实验，具体对象和动作也不能用泛化氛围替代。

已有描述缓存用于宽召回。关键动作仍要看实际候选窗口；初次正面观察与同窗加密复审冲突时保留反证并重新处理，不把新的否定简单当调用失败。尝试更短窗口失败与原窗口被否定要分别记录。

### 5.2 先语义有效，再做长度和全稿安排

输出有效候选池、待补观察、确定素材缺口和时间适配冲突。素材有合适内容但装不进句长，应记为时长问题；没有看完或服务失败，不能宣称全库无素材。

复用现有全稿编排、重复控制和多镜组合。在候选有效的前提下优化自然速度、重复与衔接，不因长度刚好就替换成不对应的对象或动作。

### 5.3 受控接入纸品动作求解

先接纸品明确动作场景，保留原句音频和句长。沿用现有实验策略：关键动作/结果原速，可压缩过程优先不超过 2 倍，必要时最多 3 倍；是否可看清仍需实际播放验收。此策略不自动覆盖其他品类，也不把达到倍率上限当质量通过。

动作边界标为 censored 或缺少开始/结束时，继续扩展观察或寻找其他候选。连续过程不可跳切为“动作完整”，结果最少帧数是检查参数，不是视觉合格证明。

首期明确接受 CFR 源及当前可验证帧率范围。不支持的 VFR/帧率组合返回明确原因；后续若引入规范化素材，保存源 PTS 到派生素材的映射，重验动作区间与质量后再纳入。禁止把不支持输入静默交给高倍速旧路径。

## 6. 原生预览与分层质检

### 6.1 预览入口

从 tools/selection_preview 抽出不依赖草稿的时间线渲染核心，放入 media；现有 --draft 入口保留为历史导入适配器，仅用于读取旧稿做对照。新生产路径不先生成临时剪映 JSON，也不依赖草稿目录。

第一期支持业务必需的硬切、裁切/位置、恒速与可映射分段速度、分轨音频、字幕和基础淡变。先固定共享能力，再扩展复杂效果。快速预览可降低分辨率，但保留目标帧率、镜头边界与音频时序；文字、包装小字和布局验收使用足够清晰的检查图或目标规格渲染。

字幕字体、换行和效果两端差异必须评估。现有近似 ASS 渲染只适合已声明范围的对照，不直接升级为任意剪映效果的最终验收器。

### 6.2 三类生产检查

- **结构与媒体**：资产可读、窗口不越界、轨道/音频完整、时序不变量和解码通过。
- **内容语义**：商品、对象、动作、结果、卖点覆盖与口播顺序；保留未知和反证。延续独立 QC 不采信选镜评分、理由和通过结论的边界。
- **实际观看效果**：实际输出中动作开始/关键过程/结果存在且可读，速度与节奏合适，口播衔接、字幕可读性、混音和布局符合要求。

对关键动作需核验实际输出帧，不仅检查计划源窗 end。纸品显式 source_frame_map 是计划，必须经重算、真实解码和输出对应验证；不得用重复尾帧或定格伪装结果停留。检验仍要覆盖整稿衔接，不能只在裁切片段里通过。

输出失败类别、句/镜头 ID、目标时间、实际源窗和建议修复阶段。语义错误回选镜，窗口错误回定窗，音频/字幕问题回对应资产，环境/服务失败走阶段恢复。不得把每种失败都处理成整稿重新生成。

## 7. 剪映导出、可编辑性与保真

### 7.1 导出器职责

将现有 application/engine.write_draft 中的 JyProject 写入抽到 delivery。保留当前安全建稿、独立素材暂存、包检查及合法交付能力；选镜、配音、字幕定时、窗口求解和内容裁决在此前完成。

导出使用原素材与各轨资产，生成视频片段、旁白、BGM 和独立字幕。保留源入出点、源余量和可调参数；专业编辑能换镜、延长切片、调速度、改字幕与混音。验收 MP4 不作为整条视频的唯一可编辑素材。

### 7.2 先验证分段变速能否表达

纸品帧域方案可能包含分段速度与明确选帧。剪映恒速/分段片段是否能保真表达，需要实测，不能由 FFmpeg 预览成功推定。

首期只接受已验证可映射的速度、连续源窗口和效果。导出前做能力预检；发现不可表达的帧映射、字体或效果，明确返回导出兼容冲突，并在生产阶段调整到两端共同支持的方案。

不默认烘焙整片。需要局部派生素材的扩展必须单独说明编辑能力损失，保留原素材和参数并经业务选择；在其获得明确接受之前，不能把它作为满足“完整可编辑”的默认绕过路径。

### 7.3 导出后仍验映射

回读实际草稿，比较源区间、目标位置、时长、速度、分轨音频、字幕和已支持视觉参数；开发验收在目标 Windows 剪映版本开稿抽查，验证原生播放与独立编辑能力。新生产核心不通过 GUI 执行编辑，也不恢复 Mac 必经流程。

导出检查发现纯映射错误时只修导出；若需改动编辑结果，退回生产循环重验对应修订。源码合并、开稿检查与生产安装分别留证。

## 8. 状态、正式交付和恢复

### 8.1 分阶段状态

拟议阶段为 planned → review_rendered → content_pass → draft_exported → draft_verified → ready_for_editor。它们是阶段状态，不直接重定义现有终态 SUCCESS 或正式交付许可。NAS/业务表等外部操作继续遵守已有配置与授权。

内容生产通过表示该时间线与工作渲染的内容合格；正式草稿交付还要求导出一致、实际包与当前素材有效、现行四项证据通过。缺素材、超时、预览和未解决窗口保持未认证或阻断。

### 8.2 兼容四项验收，避免伪造 PASS

tools/acceptance 当前检查 INPUT-IDENTITY、RUNTIME-IDENTITY、DRAFT-PACKAGE、VISUAL-QC；其中 QC 报告还须匹配实际草稿。它们继续生效。

迁移初期增加生产前置质检，导出后保留现有实际草稿 QC。内容 PASS 不能改名为旧 draft_visual_qc.json 的 PASS，也不能复制旧认证到新草稿。

稳定后可把 QC 中的媒体读取与判断内核分离：时间线和草稿各自提供真实片段输入；正式报告合同显式连接内容质检与实际导出验证。需要覆盖换窗、变速、字幕/音频变化、源变更、报告缺失和 preview 转正式等必拦反例后，才能减少重复视觉调用。现有合同尚未支持前，不删后置 QC。

不新增签名或逐文件 hash 门槛；沿用既有身份和版本合同，质量判断依赖真实内容与实际导出。

### 8.3 按依赖失效与恢复

- 换镜或改入出点：更新对应选择、窗口、渲染、内容 QC 和导出；保留未改配音。若长度变化影响后续位置，失效范围扩到受影响的后续时间线与衔接。
- 改口播/音色/倍速：更新相应音频、字幕、需求、时间求解和下游；未变源素材观察继续复用。
- 改字幕换行/位置：更新字幕、视觉布局检查、渲染和导出；修改文本必须再核对原口播，不自动改写音频。
- 只调增益：核对实际文件及长度，复验音频/渲染/导出；时长不变时不重选镜。
- 模型调用超时：保留完成的观察，沿用共享请求预算和账户槽位，不清全库缓存。
- 导出或分发失败：输入与内容修订不变时恢复对应阶段，不重做 TTS/选镜。
- 模型切换：明确区分复用历史观察和当前模型重评，保持真实来源；不将历史回复记为新模型的效果。

沿用现有有界重试与任务锁。新增局部修复受同一任务总预算控制，不能使“阶段重试 × 多轮重选”形成无上限循环。持久化阶段输入、完成情况与阻断原因；新状态接入 scheduled/dispatcher，重复触发不重新生产已通过结果。

## 9. 模块落点

保持现有功能包，不往旧平铺兼容入口增加逻辑。下列为拟新增/细分的模块，实施时允许按单一职责微调名字：

- domain/timeline.py：纯时间线、轨道事件、稳定身份与序列化合同，不依赖 application 或外部服务。
- application/production.py：生产阶段组合与局部修改；CLI/engine 保留兼容入口。
- audio：最终音频与字幕资产准备，复用当前实现。
- vision + selection/paper_action_events.py：可见事实、观察范围与不确定性；通用化通过接口演进，不复制一套模型客户端。
- selection：需求/候选适配、paper_action_windows 和现有 timing_contract，输出可编辑的确定方案。
- media/timeline_render.py：执行时间线；底层编解码只接收技术参数，不依赖 selection 的业务实现。
- quality/production_qc.py：独立的生产质检；必要解帧、采样委托 media，模型请求复用 vision。
- delivery/jianying_export.py：时间线到 JyProject；导出前能力检查，导出后比较委托 quality。
- tools/acceptance：继续协调最终四项证据；tools/workflow 与 tools/queueing 接入新的阶段状态。

源帧表等基础媒体数据适合放 domain/media；不要让 media 反向导入 selection/paper_action_windows。现有 tools/selection_preview 的跨层组合在 application/tools 适配层保留。

## 10. 实施拆分与完成标准

### PR1：独立时间线与资产准备

产出数据合同、Clip/manifest 的单向适配、最终音频/字幕准备和生产/导出预检分离；在生成时间线时声明两端共享能力。初始覆盖硬切、基础布局、恒速、旁白/BGM 与字幕。

完成标准：不导入 JyProject、不查草稿根，也能用固定输入得到完整可验证时间线。口播/字幕/镜头关联稳定，重复句不互相覆盖；真实音频时长不被估计值替代。新报告目录复用冻结分句需有回归，核对 hybrid 分支相关修复但不覆盖当前模块化实现。

### PR2：无需草稿的渲染与质检骨架

产出从时间线渲染的 media 核心和三类质检入口；保留旧 --draft 对照适配。将现有精确选帧经验落实到实际输出检查。

完成标准：使用合成媒体和一份已人工确认的固定选镜，完成无剪映草稿的完整预览；原音/旁白/BGM/字幕独立且对齐。缺帧、结果被采样丢失、无效窗口、音频错误和未支持效果必须显式失败。

PR1 + PR2 后可先用固定正确选镜贯通预览；不要把这一技术切片称为自动选镜质量已改善。

### PR3：动作事实、语义匹配与定位接入

纸品作为首个受控场景，把当前隔离工具接到候选与窗口服务；补充句内卖点顺序、冲突观察和动作边界处理。其他品类保持显式现有路径或清晰的不支持状态，不自动套纸品参数。

完成标准：同一输入下分清素材缺口、召回失败、观察未知、语义误判和时长冲突。关键/结果不被裁掉或加速，censored 边界不冒充完整动作。纸品 34 揉搓仍不合格时保持阻断，继续比较其他候选或明确请求调整内容/素材；不靠回退高倍速取得通过。

### PR4：末端导出与可编辑性

把写稿逻辑收敛为导出器，接入已通过时间线，保留实际草稿 QC 与最终四项验收。补齐支持范围内的预览/草稿比较，验证 piecewise retiming 在目标剪映版本的表达。

完成标准：完整生产循环无需先建稿，只有内容通过才尝试正式导出；草稿的源窗、速度和轨道忠实对应。编辑可分别换镜、调切点、改字幕和调混音。伪造内容 PASS、旧 QC、不同输入或有兼容冲突都不得正式交付。

PR1、PR2、PR4 可先用固定正确选镜构成最小端到端技术闭环；自动生产启用还必须完成 PR3 的真实质量验证。

### PR5：调度恢复、反馈与受控启用

接入 Windows scheduled/dispatcher 的阶段状态、依赖失效和有限恢复；复用现有句级反馈工具，不恢复人工批准文件门禁。

完成标准：重复触发、服务中断、只改字幕、只换镜、只重导出和多输出部分完成均保持正确状态。可从内容通过处恢复导出，未通过不回写完成。记录阶段耗时、模型调用、缓存命中和人工精修成本。

新路径先显式选择，默认路径在验收完成前保持原行为；两条制作路径不得对同一输出并发写入。回滚保留新报告与资产，仅切换后续制作路径，不自动回放已完成任务、不改写编辑已保存的草稿。默认切换与部署另行执行。

## 11. 验证与质量指标

### 11.1 基线与失败分类

优先复用编辑已经改过的任务及正确源窗口，再加入正常任务。小规模先验证链路，扩展到覆盖对象相近但错误、相似包装、短动作、结果短停留、多卖点顺序和真实缺素材的样本；数量按现有可用材料定，不为凑样本虚构标签。

对每个错误分层定位：

1. 原素材有无正确片段。
2. 正确源窗是否进入候选。
3. 给定正确候选，观察与用途判断是否正确。
4. 最终截取/变速是否保留必要动作和结果。
5. 正确时间线经导出后是否仍一致。

可先注入人工正确片段，分别绕过召回和语义匹配，验证时间线、预览与导出。这样避免将上游识图错误误判为剪映底座问题。

### 11.2 指标

- 正确候选召回率，真实缺素材与漏检分别计数。
- 编辑认可的镜头比例、错误画面自动放行比例、正确画面误拒比例。
- 动作和结果在实际播放中的完整/可读比例；不能只统计证据区间是否在窗内。
- 每条换镜次数、精修分钟和可直接接手比例。
- 预览与草稿的时间/参数偏差、媒体可打开率、独立编辑能力。
- 有效内容通过到可编辑交付的耗时，以及模型、渲染、排队和重复计算成本。

保留现有 debug/holdout 分离。固定旧模型观察的离线回放验证程序行为；识图或提示词效果需要新的真实像素观察和独立标签。具体质量阈值用同一批基线和编辑判据制定，首轮没有数据时不承诺准确率或加速倍数。

### 11.3 实施验证层次

- 纯合同与求解：同源数据、序列化、单位转换、重复句、多镜/跨句、边界和失败分支。
- 合成媒体：明确图案/帧号、CFR/非零起始 PTS、目标帧量化、受保护末帧、真实解码后的音画对应；VFR 等不支持情况明确拒绝。
- 业务集成：真实候选观察、完整预览、独立 QC、编辑对动作/结果与节奏的判断。
- 输出集成：目标剪映版本开稿、原生播放、分轨编辑和现有共享交付检查。

功能 PR 按 [测试策略](../test.md) 执行两套 uv 离线回归及 tools.check_architecture；新增/调整状态或闸门要有必拦反例。发版时再做包外合包与全新解压。开发测试不启用宿主计划任务、真实队列或业务写回。

## 12. 主要风险与处理

- **帧域方案在剪映不能等价表达**：PR1 确定共同能力，PR4 实测；不把任意选帧自动转换为粗略平均倍速。
- **预览与剪映视觉差异**：逐类验证字体、换行、位置、裁切和效果；未验证功能不进入默认正式路径。
- **模型误读动作**：保留帧事实、反证和未知，用真实播放与人工对照评价，模型自报 confidence 不作真实标签。
- **短口播放不下完整动作**：先找更紧凑的正确候选/编排，必要时明确素材或文案需要调整；未经业务决定不改原音频，不降低完整性换取通过。
- **新旧报告误复用**：修订与实际资产绑定，保留当前四项验收；减少后置 QC 必须先完成合同迁移和负例验证。
- **局部变更引起全稿漂移**：以稳定身份和依赖闭包处理，时间改变则重验后续衔接；旧通过只对未变输入有效。
- **改造范围过大**：先用固定正确选镜做最小技术闭环，再验证自动选镜质量；保持模块内迭代和可回滚路径。
