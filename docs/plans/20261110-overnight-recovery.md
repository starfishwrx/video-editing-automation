# 夜间批量任务自动恢复修复

## 问题与结果范围

本次从夜间任务的阶段报告及补跑中整理默认入口的可修复失败。历史45条首轮19条制作OK、15条ERROR、11条在准备/参数阶段BLOCKED；人工修复后的15条补跑新增8条制作OK，历史合计27条。这里统计制作状态，不等于正式分发，也不能作为本候选重新跑45条后得到的成功率。

## 失败与处理

| 失败模式 | 默认入口的修复 | 验证 |
|---|---|---|
| 视频后缀静态图让同商品任务全受阻 | ffprobe识别后完整单帧解码，保留warning并跳过；损坏或未知来源继续阻断 | 三个历史错误源只读重放确认静态图；损坏MOV及截断图片反例继续阻断 |
| 个别视觉回答不可审计 | 有限单镜头重问，预算内剔除；商品交接保留输入绑定，不对每条任务重复问 | 冷准备、复用、改变来源、缺绑定、网络失败、已有排除加新增异常的行为覆盖 |
| 实验内部派生末帧未在抽样表 | 独立边界与连续性派生帧分开验证，一帧内对齐或重问一次 | 两组历史事件事实编译；无连续性或较远未知边界仍拒绝 |
| 长片短动作漏采样、旧缓存不兼容 | 加密取样、倒水窗补帧、邻接召回；新采样scope隔离旧pair/motion及拒绝记录 | 取样、缓存恢复及联合配对测试；邻接不作为同次实验证据 |
| 截早动作后仍需人工重选 | worker把同镜头遗漏区间交给补选；实际补看目标帧，优先独立复核原镜头 | 100秒源90–91秒窗口实际抽帧及补选入口；未确认不可通过，替代失败不丢已确认事实 |
| 单帧舍入差导致可行放置被拒 | 已知源帧率下一帧内收敛并记收据；未知帧率保持阻断 | 历史18.292ms端点重放及120/240fps、未知帧率反例 |
| 字幕内容正确却因尾部空白拦住 | 布局预期与结构读取端统一首尾空白，内部文字/换行仍精确比较 | 旧原生草稿第6句回读及改字/改内部换行反例 |
| 旧配音静音处理与测量不一致 | 沿用main已合入的最终配音定长/冻结及连续静音修复，不调整五帧闸门 | 三条历史任务39句缓存音频在新目录完成处理并通过五帧检查；不代替整稿QC |
| 阶段时序失败被日志路径误报草稿错误 | 保留结构化阶段分类及明确不可重试；环境保护优先 | 历史三个时序误分类回放、语义分类和凭据/来源改变保护 |

## 默认调用链与验收

现有定时/单条/批量入口继续进入dispatcher，按商品准备素材；worker保留候选及排除警告，CLI重验来源；选镜失败按已有阶段冻结音轨恢复；QC只把受影响句及合法同镜头提示交回补选。目标图片仍需重新判断，实际新草稿仍需独立QC与正式PASS条件。

源码、离线回归、历史事实重放和真实无人值守制作分别记录。来源图片、响应正文和私有路径不进入仓库。完整离线回归、独立审阅及Windows CI结果写入PR。本轮不安装生产，不写业务队列或NAS/飞书，不承诺下一批一定达到某个比例。

## 仍会停止的情况

余额/凭据不足、已耗尽的模型重试、未知/损坏素材、动作证据确实缺失、原速关键阶段无法塞进冻结配音、源变化和最终QC拒绝仍保留阻断。JSON/网络异常沿用已有两次请求账本和阶段预算，不因扩大搜索而无限重试。音色无法唯一映射必须在付费处理前修正，不能猜一个音色继续。
