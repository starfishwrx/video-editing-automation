# 按口播需求识别画面并验证最终剪辑

状态：显式入口已实现，卫品42隔离验证结束，整片改善未通过。基线为 `feat/programmatic-timeline` 的自动BGM补齐提交；新分支 `feat/purpose-driven-selection`。

每句口播先明确需要看到的动作、结果或包装标称，再到该任务指定素材中寻找对应片段。剪完后重新看实际输出，确认卖点没有在截取或变速时丢失。目标是减少错配及动作不完整；素材没有证据时明确保留缺口。

## 本轮实现与边界

复用 GLM/Qwen 直连、账户限流、带时间戳抽帧、调用缓存、独立时间线和 FFmpeg 渲染器。新增可独立运行的需求编译、定向识别、选窗及输出复核入口；不部署、不启动队列、不写NAS或业务表，不覆盖原稿。现有业务选镜默认保持原状。

1. 将原文按既有切句口径拆分，每句记录稳定编号、需要看到的事实、展示/动作结果/标称等证据类型。体验表达接受贴切展示，持续一整天、绝对不反渗等结论不能由短演示无限外推。
2. 素材缓存先核对本任务实际目录及文件。描述仅用于召回；有缓存则复用，没有缓存则生成任务局部画面索引。一次源片粗看可服务多句，粗看给出的时间段只是搜索线索。
3. 将完整文案需求带入识别，按句定向复核候选的连续源窗，记录可见事实、各卖点的支持/不支持/不确定，以及一次完整动作和结果。动作观察不接收目标句长，避免为了配音编造短动作。
4. 用真实配音时长求解：关键动作和结果原速，其他过程优先不超过2倍、最多3倍；不靠定格、删结果或超速放行。未选中的需求留缺口；预览可用明确标记的无证据占位，不算匹配。
5. 渲染后从实际输出重新抽帧。新调用只收到原文、证据要求和实际输出，不接收选镜理由、分数或通过结论。检查卖点、动作、结果和字幕时序；抽帧不能认证采样间的所有行为，完整播放/听音另记。

## 卫品42验证

锁定业务表第42条“小马”任务，读取当前原文、素材目录及音色，不使用其他日期的同商品素材。初查该任务没有历史草稿/配音，指定目录有92条源视频，旧分析属于另一日期，不能冒充缓存命中。

按表格的直率英子、1.2倍速生成一次配音并归一，两路共用其最终音频、句长、字幕和同一BGM。已有流程能够物化时记录其真实基线；否则只生成明确标注的粗召回诊断参考，不把它称作历史原稿或现行生产成片。不得通过削弱基线夸大收益。

重点检查纯棉标称、超薄/透气、吸收及不反渗、到手量感。记录逐句候选来源、实际复核次数、源窗、局部倍率、缺口及输出复核。最多三轮定向候选；失败保持失败，不重新全库识别或合成配音。

交付：可播放参考与新方案预览、重点片段、逐句变化/证据表、调用与缓存统计、实际结果报告。评价分为明确改善、未改善、证据仍不足；程序通过不代表内容或人工验收通过。

## 验证与接续

离线反例覆盖错商品/旧源、未知需求编号、越界证据、不完整动作、保护部分加速、超过3倍、无候选、漏句、输出修改后旧复核失效及固定音轨不变。运行仓库规定的两套测试与架构检查，独立 code/privacy review 后提交。真实任务数据和媒体留在包外，不写入公共源码。

后续默认接入与部署依据真实效果另行决定。千问的[视频与时间戳输入能力](https://github.com/QwenLM/Qwen3-VL)提供基础，本轮使用项目已有直连接口和带源时间戳画面，不宣称已经运行原生视频接口或做到逐帧语义识别。

## 实际结果

卫品42的13句最终配音共19.489048秒；两路585帧预览及重点片段已生成，旁白、BGM、混音和字幕文件逐字节一致。新方案11句选用原速画面，吸收/反渗两句在本轮完整动作与3倍上限内未找到合格时长方案，保留诊断占位。

统一 `purpose-output-review-v3-picture-frames` 抽样复核：现有选择器11句支持、2句待核实；新方案及一次备选修复均9句支持、4句待核实。薄透判据仍存在展示体验与性能实证分歧，持续一整天的效果也没有得到核实。现有选择器本来就有逐句复核且沿用较高速度范围，两路又共享了文案条件索引，因此不能把结果单独归因到视觉模型是否读文案。

结论为整片未提升，不切换默认生产。程序检查、单例抽样结果和人工完整观看分别留证；同素材的跨句实验编排、动作相位紧凑化和判据一致性仍需后续验证。没有写NAS、业务表或部署。真实任务快照、视频、逐句表、409次本地请求账本及结果报告留在工作区索引所列的包外验证目录，不进入源码包；该请求数包含实现调试、多轮对照/复核，不能当作单次生产成本。
