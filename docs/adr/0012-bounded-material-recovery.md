# 0012 有界素材准备恢复与源帧边界对齐

- 状态：已采纳，源码候选；真实成片和部署独立验收
- 日期：2026-11-10
- 关联：[默认选镜](0002-ai-selection.md)、[短窗放置](0006-short-window.md)、[实验组](0007-experiment-groups.md)、[有界恢复](0009-frozen-input-recovery.md)

## 背景

整库准备因视频后缀的静态图片或少量不可审计回答失败；实验事件要求连续，却同时要求派生末帧必须在抽样表里，造成不必要的拒绝。长视频稀疏均匀采样还会漏掉短倒水动作。

## 选择与原因

时长失败后，只有 ffprobe 成功确证的非视频可跳过并留下警告。静态图还须是图片格式且可完整解码为单帧，不能凭损坏视频或图片的头部判断。未知、损坏或读取失败继续阻断，所有源都无有效候选时不能就绪。

不可审计回答最多单镜头重问两次，JY_VISION_REASK_LIMIT 可设0至2。每产品最多处理 max(1, min(24, 镜头总数整除100)) 个镜头。持续不可审计的镜头保留 pending 状态，需排除标记和匹配警告同时存在才能从候选池剔除；不缓存为有效观察。超预算、禁用重问、传输及解析失败继续阻断；至少保留一个有效镜头。独立成片 QC 和正式 PASS 条件保持生效。

实验事件验证每个起点及最终终点，内部终点由下一起点减一推导。未展示边界只可移动至一帧内的已展示帧，联动窗口和事件标记；否则最多重问一次并拒绝仍无效结果。放置证据端点只容许一源帧内的舍入收敛，裁切后区间仍需非空，保存调整收据。无法取得有效源帧率时不允许端点容差，继续阻断。

长片配对从8帧提高至最多14个基础帧，定位倒水仅作补帧线索，最多追加6帧；邻接文件只用于召回，不能代替实际联合视觉证据。配对预算3增6。配对尝试作用域加入采样协议版本，使旧配对与动作缓存及拒绝记录保留但不冒充新采样证据；恢复时重新观察。普通连续组替换任一成员时重规划整组，跨文件实验组仍保持已接受邻句锁定。

## 代价与验证

重问和配对增加有界模型成本，剔除减少候选覆盖；本候选未证明整体提速或成片质量提高。两个恢复测试模块覆盖重问、缓存、读取错误、超限与越界拒绝，既有组/QC/正式交付回归继续执行。源码候选不等于生产部署，离线测试不等于真实视觉或剪映编辑验收。

## 同次变更的自动恢复补齐

同商品预处理交接给worker与CLI时，保留排除警告及既有视觉输入键绑定。来源、窗口、规则或模型变化后重新分析；全新冷准备仍可重新观察，排除不进入有效视觉缓存。已保留排除计入本产品总预算，新增排除不得叠加突破上限；任何就绪路径都校验总量及至少一个非排除镜头。

局部QC判定证据不足或降级时，允许把同镜头遗漏的动作窗作为召回/取帧提示。先验证原句、源绑定、原镜头及合法动作区间，再实际抽取目标窗首中末帧并优先单镜头复核；不能只把时间提示塞进整段稀疏抽样的prompt。目标帧使用独立媒体缓存协议。复核未确认仍阻断或转其他候选；已确认但时长不适配时保留原观察给既有短窗/局部变速求解，不被无匹配的替代池覆盖。原口播、已接受邻句与独立QC继续保留。

批量结果优先保留合法阶段的failure_class/failure_code，包括不可重试失败。素材变化等环境保护仍优先，明确retryable=false或预算耗尽不得因日志含timeout而变成可重试。素材准备失败摘要指向候选报告及实际缺项，不再用巨大来源清单的stdout尾巴隐藏根因。

源码候选整合既有同镜头重裁和本地媒体副本QC绑定；非原生分发包不再强制要求无用途的fix_local脚本，但实际媒体、当前草稿、独立QC及正式交付验收仍需通过。详见[夜间恢复验证](../plans/20261110-overnight-recovery.md)。

补看后的候选求解和最终组装MUST受有效review_window_us约束，continuation入点只能进一步收窄，MUST NOT重新打开原素材中未复看的前缀；旧无局部窗口的观察MUST保留原范围，非法或越界局部窗MUST拒绝。关键词及详细边界见[AI编辑合同](../../packages/video-v1.5.3/docs/AI_EDITOR.md#补看窗口边界)。

## 2026-11-12 同一商品内并行准备原片

批次按商品、素材目录和有序素材清单共用一个准备任务。商品锁持有到视觉观察完成；源文件按既有身份、切镜参数和协议单独加锁、缓存。每个源负责自己的切点、代表帧和诊断。完成顺序只用于发现失败和补派下一条，最终按清单顺序编号、汇总并发布。发生异常即停止补派，等待已开始的源退出；重试可复用已完成的源。

并发 FFmpeg 探测、切镜和抽代表帧时，进程内的 libmediainfo 读取需要互斥。该库共享选项，在同一原片上并发读取曾返回无效 XML，使探测丢失旧写入器的较短时长。仅把这次库调用串行化，继续采用两种写入器可用视频时长的较小值。

冷源以 `source_prep_slots` 限制全机同时处理的原片数。抽帧拼图和 QC 继续受 `prep_slots` 限制。两个阶段沿用同一目录的文件锁，冷源优先取高编号槽；当冷源预算高于普通预算时，0 号槽留给普通媒体工作。因此两类工作混跑最多占冷源预算加一个媒体槽。只设置旧 `prep_slots` 的策略会同时约束两者。每次 GPU 解码另受解码槽和显存预算约束。
