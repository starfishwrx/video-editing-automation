# 跨批次保存素材观察

2026-11-16，采用。Windows 主机使用 SQLite 和本地媒体文件保存逐窗观察。正式入口默认沿用安装目录的共享视觉缓存，任务工作目录记录本次报告。显式设置 JY_VISION_CACHE_DIR 可隔离实验，JY_MATERIAL_EVIDENCE_DB 指定独立数据库或用 off 关闭证据库。

初看、包装文字、候选复核与实际切片 QC 分级入库。按商品及 SKU、原片 SHA-256、原片时间窗和观察协议查找，当前任务的素材清单界定候选范围。历史视觉缓存迁移需要可重新验证的冻结素材摘要。检查观察来源及条件，只有完整、可绑定的画面依据能跳过重复看图；新条件进入局部像素复核。放置求解和独立成稿 QC 在每个任务内运行。

SQLite WAL 和本机文件锁支持并发。缓存采用本机盘，原片可在 NAS。内容摘要和证明文件会增加首次导入 I/O。历史细看记录缺少精确动作锚点时仅参与候选检索。按批次记录命中、缺口、实际模型 HTTP 请求以及最终 QC，区分跨文案的文字判断与像素复看。

纯包装外观评价共用一个按商品、原片时间窗、采样时刻和生效规则绑定的画面请求。保留具体设计、可爱装饰及包装上的联名原文，逐句重新绑定卖点及展示时刻。合格的密集历史记录也可用于外观复核。新增动作、规格、质检反馈或局部补查继续走逐句细看。

外观评价若指定某个角色款，同窗内同时看清该角色图案和包装上的对应名称也可支持该款式。口播直接宣称联名关系时走原有逐句复核。拼图显示的毫秒时间仅在唯一对应采样帧时还原为原片微秒。

背面或侧面以说明、授权小字和条码为主体时，按外观卖点返回证据不足。另有可定位的正面设计画面时，按对应时段单独核对。

“可爱”用于纯外观评价时，同商品包装正面的明确展示足以支持口播。卖点拆解中的示例角色不额外约束这个展示窗口。口播明确点名联名、功能或规格时仍要分别提供证据。
