# 2026-10-26 项目与 PR 环审

结论：合并纸品 #15、会议 #18、视觉并发 #21 的业务能力，去掉多层哈希门槛与 ASR。Windows 为主要运行环境，保留既有 UNC/反斜杠与运输行为。源码合并不再要求先完成两条真实成片或剪映 GUI 验收；生产安装和效果验收另记。

## 判断依据

采用工作区 T02（结果确定性）、M05（简单即认知效率）、X04（真实用例）与 V02（可验证性），配合 AI 编程方法论和 Skill 写作指南。检查应能发现实际素材、时序、字幕或交付问题；哈希一致无法证明画面或字幕正确。

## 本次修复与取舍

- PR #15 与 #18 有代码冲突：合并后保留稀缺卖点复用判断、纸品场景倍率及中后段偏好；补齐整稿提示词的纸品规则，以及给模型看的技术窗口中的纸品倍率。
- PR #18 的 ASR 撤销：字幕直接使用原文，以完成倍速、静音与响度处理后的每句 TTS 时长定区间。一句多镜只写一条连续字幕；保留统一原生字幕轨。移除 faster-whisper、模型下载、CUDA/CPU 识别回退、词识别校对与 ASR 缓存。
- PR #21 保留媒体准备与 API 并发分离、按完成顺序保存断点、QC 乱序归并；删除模块导入时读取并哈希源码的诊断字段。
- 选镜移除逐次全视频 SHA、提示词与拼图哈希证明、收据/多镜组合自签、规则内容哈希门槛。素材发生变化改用路径、大小、修改时间判断，窗口、倍率和卖点覆盖仍直接检查。
- 发包只保留一份路径清单、版本和目录边界检查；删除逐文件 SHA 清单、源码树哈希、多轮源目录/元数据哈希对照。ZIP CRC 与一份可供下载核对的 ZIP SHA 保留。
- 安装诊断直接比较少量必要模块的实际内容，避免维护第二套文件哈希账。生产 Eval 不再要求源码树和逐文件哈希；现有可选 Eval 接口保持兼容。
- 为避免重复模型调用的缓存键、草稿修改后防止误用旧 QC 的小型元数据摘要、NAS 运输完整性与任务关联记录保留。它们各有实际用途，不作为视觉效果或源码合并的凭证。

## 验证范围

本地使用 uv 冻结依赖执行两套回归及字幕、纸品、并发的重点检查；主要验收以仓库 Windows CI 为准。Mac 上已知的 Windows 路径夹具差异记录为平台限制，不为通过这些夹具改变生产路径语义。真实 TTS/GLM、剪映全选移动保存重开和生产任务不在本次源码验证范围。

字幕采用句段级 TTS 时长，不宣称逐字对齐。较长文案需先规划成可读口播句段，再合成对应配音；不会用字符数均分伪造词时间。飞书会议原始文档当前缺读取授权，本轮核对仓库会议计划，并以用户再次明确的去 ASR 要求为准。

本地结果：两套发现共814项；在 Mac 上排除8项已知 Windows 路径夹具后，806项运行通过，其中2项按原有环境条件跳过。字幕、窗口、纸品和并发测试均执行。包目录清单校验、生产 Eval 读取新清单、冻结依赖检查及 CLI help 均通过。最终合并以整合 PR 的 Windows CI 为准。

独立代码审查补充两处实际缺陷，已修复：纸品配置坐标需要传入原生字幕写入器，保证写入和回读采用同一位置；JyPoll 批次身份要在仍有同批待处理任务时沿用，不能因一条任务完成离开查询结果就重置 BGM 去重。批次状态使用一个普通 JSON 文件，不增添哈希校验层。字幕写入回读与纯 PowerShell 批次夹具覆盖这些情况。
